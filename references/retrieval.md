# 证据与检索规则

本文件说明：拿到一道题后如何判断需要什么证据、走哪条最短路径，以及已实测的官方接口清单。

## 先分流：题目需要什么证据

分流不看题目"看起来难不难"，只看**缺什么证据**。已经有充分原始证据的题目直接答复，不重复检索。

| 任务类型 | 什么时候属于它 | 最短可靠路径 |
|---|---|---|
| `calculation` | 题内数据和关系足以推出结论 | 直接计算或逻辑推导；必要时一次本地复算。不外搜 |
| `dataset` | 题目给了数据文件，问人数、比例、极值、分组 | 取得正确文件一次，核对列名与样本范围，本地一次聚合全部所问指标 |
| `basic-rule` | 已有适用规则卡或官方证据能判断 | 引用规则卡结论；规则卡不覆盖时才查官方说明 |
| `help` | 问功能、界面默认值、格式支持、匹配语法 | 对应产品与版本的官方指南；只有需要看实际菜单时才开界面 |
| `record` | 已知 DOI、完整题名、编号，问登记字段 | 官方 API 或记录页直达；必要时精准检索以区分同名对象 |
| `statistics` | 问组合条件的数量、排名、分布、被引量 | 保持题目全部条件的官方 API；接口不覆盖的条件用实际结果列表 |
| `fulltext` | 问参考文献顺序、全文结论、图表、页数 | 确认文献与版本，只取所需文字、元数据或相关页 |
| `mixed` | 不同选项分别需要推导、说明、记录或统计 | 按选项拆开缺口，共享同页资料，不重查已证实的部分 |
| `clarify` | 缺对象、时间范围或版本，且会改变答案 | 指出关键缺口，继续核验不依赖该信息的部分，不补造条件 |

分流时的几个常见误判：

- 规则题里提到某数据库，**不等于**要去实查该库；先核对已有官方说明。
- 计算题里出现"某检索系统"，**不等于**要开浏览器。
- 给了论文完整题名，**不等于**要打开专业检索。
- 固定论文的作者、刊期、同一版本全文可复用已有记录；但**现任机构、计数、排名、有效状态必须按题目时点核验**。

## 官方 API 与指南

需要补证时用已知端点直接取所需字段，不先浏览 API 根页、不逐站探测接口。官方 API 是独立渠道：浏览器受阻不代表 API 不可用，反过来也一样。

下表只有标注"实测"的行经过本机实际请求；其余是端点定位，使用前须自行确认当前可用性与限制。

| 来源与需求 | 端点 | 实测情况与适用范围 |
|---|---|---|
| Crossref：已知 DOI 的登记题录 | `GET https://api.crossref.org/works/{doi}` | 单条 JSON 实测 200。核对 `message.DOI` / `title` / `author` / `container-title` / `published-*`；字段缺失时转出版方或全文。**不等于**知网等指定库的统计口径 |
| DOI：解析到登记地址 | `GET https://doi.org/api/handles/{doi}?type=URL` 或直接 `https://doi.org/{doi}` | 中文 DOI 的 URL 解析实测 200。核对 `responseCode` / `handle` / `values`；返回地址只用于定位，目标记录的实际字段才算证据 |
| PubMed：检索与题录 | `https://eutils.ncbi.nlm.nih.gov/entrez/eutils/` 下的 `esearch.fcgi`、`esummary.fcgi`、`efetch.fcgi` | 端点定位可用，官方指南已停更，限制以当前说明为准。本机 ESearch 网络/TLS 失败，**不要每题盲重试** |
| PubMed：字段与检索翻译 | [PubMed User Guide](https://pubmed.ncbi.nlm.nih.gov/help/) | 按对应段落核对。用 ESearch 时检查 `querytranslation` 与警告；**API 默认顺序不等于网站 Best Match** |
| arXiv：ID 与版本元数据 | `GET https://export.arxiv.org/api/query?id_list={id}&max_results=1` | 本机实测 **429**，视为限流，不要循环重试。Atom 元数据不能代替 PDF 内容或页数 |
| 世界银行：国家×指标×年份 | `GET https://api.worldbank.org/v2/country/{country}/indicator/{indicator}?date={year}&source={source}&format=json` | 指定条件的单条 JSON 实测 200。核对指标定义、单位、`sourceid` / `date` / `value` / `lastupdated` |
| OpenAlex：题名 → 引文数/年份/DOI | `GET https://api.openalex.org/works?per-page=3&select=id,display_name,publication_year,cited_by_count,doi,type&search={title}` | 免密钥，4 条题名查询均实测 200。读 `cited_by_count` 前按 `display_name` 与 `publication_year` 核对命中条目。数值属本库口径，与 Semantic Scholar 实测差约一成，**不能替换题目指定工具的数字** |
| Semantic Scholar：题名 → 引文数 | `GET https://api.semanticscholar.org/graph/v1/paper/search?limit=3&fields=title,year,citationCount,externalIds,venue&query={title}` | 无 API key 时限流严格：4 次查询实测仅 1 次 200，其余 429。按 `Retry-After` 或指数退避，单次任务最多两次重试。**429 不等于论文不存在或引文数为 0** |
| Connected Papers：检索页引文数 | 页面 `https://www.connectedpapers.com/search?q={query}`，读条目行的 `<n> Citations, <m> References` | 两次独立查询实测成功。**无公开 API**（所有 `/api/...` 返回首页 HTML）。图谱按相似论文聚类，不保证含指定论文，**不可用图谱节点反推候选项** |
| 维普：检索功能与语法 | [官方检索规则](https://www.cqvip.com/helpcenter/advancesearch) | 已读实际正文。基本/高级/专业模式分别取证；只对应该产品，不与旧平台或智立方互套 |
| 知网、万方：产品指南 | 知网 `http://service.cnki.net/helpcenter/`；万方专业检索页的使用说明入口 | 尚未取得充分指南正文，使用时确认当前界面。搜索结果只用于定位官方指南 |

### 调用要点

- 参数用**本题**的实体、日期、类型与排序；中文、DOI 和检索式走 URL 编码，不手工拼接未转义表达式。
- 统计题与"第 n 条"只有在**同库、全条件、查询解释、排序、分页都一致**时才走 API，否则读网站实际结果。
- 一个库的被引量不等于另一个库的被引量。接口返回 `null`、字段缺失、加载中或失败，**都不是零值和零结果**。

### 限流与降级

免密钥接口的限流要有退避，并准备备用渠道。遇到 429 按 `Retry-After` 或指数退避（间隔至少加倍），不要立即循环。需要同一指标的第二来源时用 OpenAlex 交叉印证**结论方向**；它是另一套口径，只在题目未指定来源时作为独立证据。

**搜索引擎不可靠。** 实测 Bing、百度、DuckDuckGo 在连续查询后会转为人机验证页——返回正常 HTTP 状态，但正文是验证页而不是结果。不要把验证页当作"无结果"，也不要在多个引擎之间反复重试；改为直接访问候选官方站点，必要时先观察再定位。

## 全文与页面核对

题目问"第 n 页""最后一个单词""文件大小""共几页"时，答案就在指定版本的全文字节里。以下三条按实测得出，违反任一条会直接答错。

**扫描件无文本层时改用页面图像。** 先试文本提取；结果为空（不是零星缺字）说明该 PDF 没有文本层，此时**不得**据此判断"页面无内容"，应导出该页图像后识别。老学位论文、古籍、地图、公报的扫描件普遍如此：某 1993 年学位论文 153 页全部为 CCITT 传真压缩图像，文本提取全空，逐页导出图像后才读到内容。反向也要区分：文本提取到一部分而缺另一部分，属于提取质量问题，不是无文本层。

**按题目页码定位前先验证页码偏移。** 印刷页码与 PDF 物理页序常因前置页（封面、目录、罗马数字页）而不一致，直接按 PDF 序号取"第 n 页"会取到错误的页。做法是取几页的页脚实际数字确认偏移，再按偏移换算，并把该页页脚数字作为定位证据；同一次任务里偏移通常恒定，但仍应至少核对两页。答复中区分正文页码与文件物理页码。

**指定工具时用该工具的口径。** 题目写明"在某工具/某数据库中"时，同一指标在该工具与其他来源的数值可能不同（实测某文献引文数在两个来源间相差约一成），排序可能一致而绝对值不一致。此时以**题目指定工具**给出的数字为准，其他来源只用于交叉印证方向。若指定工具不可达，如实说明并标明改用的来源，不默认为等价。

## 定位与核验

结果页或详情页开新标签时，用点击前监听加当前条件回显或记录标识共同确认目标；只在已确认的结果容器里定位记录。列表里出现同名链接时，按篇名、作者、年份或唯一 ID 区分，不按链接顺序猜。

题目问"第 n 条"时保留当前查询、排序与每页数量，明确分页后再读取该条，**不能额外收窄条件**再声称排名成立。

旧题的延迟弹窗和旧列表不作当前证据。结果页验证完成后重新观察，从原步骤继续。

## 组合检索与统计

只在需要组合字段、范围或逻辑关系时使用专业/高级检索。DOI、完整题名和唯一编号可以直达或普通精准检索，不为简单定位切换模式。

- 先选题目要求的资源库，再填检索式和日期条件。字段、精确/模糊、同义词扩展、文献类型与排序必须忠于题意；统计题不能擅自增加限制或关闭题目要求的扩展。
- **各库语法分别核对**，不把知网语法套到万方、维普，也不套到同厂商的另一产品。含引号、括号或运算符的检索词按当前官方帮助转义。
- 正常零结果可以检查语法和拼写后按题意放宽；**语法报错、加载中和权限错误不能记为 `empty`**。
- 题目问某字段的结果总量、排名或第几条时，严格保持原检索式与排序，不为定位单篇而收窄统计口径。

只问是否超过阈值时，条件一致的官方总数字段足够，不展开逐条列表；只问前 n 名则读对应排名范围。候选项用于读取和比较字段，**不能**把候选项附加成筛选条件来论证"全库最高"。

## 单选、多选、判断

- **单选**：选出唯一应选项，并检查其他选项是否应排除。出现多个可选项时标明冲突或题意缺口。
- **多选**：逐项核查全部选项，记录每项应选、应排除或未知。只证实部分应选项不能标为整题已核验。
- **判断**：判正确须覆盖完整陈述及适用条件；判错误可用足以推翻原陈述的真实反例。反例必须落在题目范围内，不能用不同版本或不同产品代替。
- **否定题**："错误的是""不包括"按题干评判该选项是否应选，避免把选项陈述的真伪直接当作选中与否。

## 置信度与答复

先完成必要补证和全部选项的核验，再一次生成简短答复：

```text
答案：C。
依据：（题库命中写"题库命中·原题号"；推导写"题内数据推导"；检索写一句关键依据）
来源：（题库 / 具体原始页面 / 规则卡）
置信度：95%（高）
```

| 情形 | 置信度区间 |
|---|---|
| 答案与全部选项已依据实际捕获的来源核验 | 90–99% |
| 证据或逐项核验仍有缺口 | 60–79% |
| 只有记忆、摘要或未达要求的证据 | 30–49% |
| 访问或授权障碍使核验未完成 | 20–49% |
| 来源或结论存在未解决的冲突 | 40–59% |

**置信度表示对本题证据完整性的估计，不是经过统计验证的正确率。** 证据不足时写"待核验"并指出一个会改变答案的关键缺口。不为提高置信度、凑来源或补截图而重复查证。

页面打开、证据已捕获、helper 登记成功都只是过程状态，**不构成"已核验"**。未访问的链接不得声称已核验。

# 证据与题型规则

## 权威路由

先识别所需证据，核对本对话已有原始证据是否覆盖当前对象、字段、条件、版本和时点，再选择需要补查的事实归属。题目提到某数据库或工具，只有尚缺证据的具体记录、返回值、字段、数量和排名需要进入其检索或分析模块；功能、菜单、定义和检索语法先复用适用的官方说明，有缺口才读取该产品帮助或当前界面。其他事实优先负责该事实的政府机构、出版方、标准发布机构及原始数据；没有固定预检名单或预检通过门槛。

## 先分流，再选流程

下面的检索路径只用于证据缺口。主代理或子代理已经实际读取的官方网页、官方API原始响应、授权文件及可复算材料，只要满足本题对象、条件、版本、时点和选项范围，即可直接支持答复。主代理验收这些材料，不重复同查；只给答案字母、来源首页、搜索摘要或自称高置信度仍需补证。

官方API核对真实请求、错误状态、查询解释及所问字段。例如完成日期与发表日期不同，作者单位不自动等于第一作者单位。网页/文件核对实际对象、所需完整列表及截断范围。截图、helper来源登记和文件落盘是归档方式，不是所有渠道的事实核验门槛；不为迁移证据格式或补截图重新查询。真实工具结果保留原URL、摘录/响应和取得时间，未记录到秒时注明实际精度，不重新请求来补时间戳。

| 任务 | 触发条件 | 最短可靠路径 |
| --- | --- | --- |
| `calculation` | 题内数据及关系足以推出结论 | 直接计算/逻辑推导，必要时一次本地复算；不外搜、不强制helper |
| `dataset` | 指定数据文件中的人数、缺失值、比例、分组或极值 | 取得正确文件一次，核对列名、编码和样本范围，本地一次聚合全部所问指标；只在问Excel操作时使用其界面 |
| `basic-rule` | 已准备规则或已有适用官方证据能判断，未要求范围外的厂商、版本或具体记录 | 引用适用规则卡claims或复用网页证据；均不覆盖时才查官方说明 |
| `help` | 功能、界面默认值、格式支持、登录要求、匹配语法 | 对应产品/版本官方指南；实际菜单、当前默认值或权限差异需界面时再打开 |
| `record` | DOI、完整题名、编号、资源库存、登记字段、具体作者机构 | 所问字段齐全的官方API或记录直达，必要时精准检索区分同名对象 |
| `statistics` | 组合条件的数量、排名、分布、被引量或结果第n条 | 指定库官方API须保持完整口径；网站排序或接口不覆盖的条件用实际列表/专业检索 |
| `fulltext` | 参考文献顺序、全文结论、具体图表、标准条款或PDF页数 | 确认文献与版本，只取所需文字、元数据或相关页；视觉证据不足才渲染 |
| `mixed` | 不同选项分别需要推导、说明、记录或统计 | 按选项拆证据缺口，共享同页资料，补缺口而不重查已证实部分 |
| `clarify` | 缺少对象、行业、时间范围或版本，且会改变判断 | 指出关键缺口，继续不依赖该信息的核验，不能补造条件 |

分流不以题目“看起来简单”为依据。例如规则题提到知网先核对已有对应官方说明；计算题含“某检索系统”不意味着实查；有论文完整题名也不必打开专业检索。固定论文的作者机构、作者名单、刊期及同一版本全文字段可复用原始记录，当前任职机构、计数、排名及有效状态按请求时点核验。少量来源能覆盖整题时，不为了并行数额外开站。

题内引用先读已给的文献类型标识、作者文字、题名、年份、卷期和页码；“等”不能推出作者总数，单位及期刊出版频率不从题录格式推断。明确只问所给材料能够推出什么时，不能外查后把新增事实当成材料本身提供；“借助引用可获取”可能允许由引用定位原文，先按题干范围判断，有歧义时说明关键疑点。

默认最多5个网站并行、任务标签页最多5个，同一网站串行。当前操作、登录验证及证据尚未读完的页面受保护；并行仅用于独立来源，不覆盖同库查询条件，也不减少逐项核验。

需要浏览器交互时才启动或恢复session，通过 `session.page(sourceId)` 按需打开相关站；默认不调用 `preflight()`。完整123条基础目录与站点索引用于路由。目录外官方来源在当前Page读取并核实身份即可支持答复；需要helper管理该页时才用 `session.addSource({id,name,url:page.url(),domains}, {page})` 登记，不登记未打开入口。通用搜索可辅助找官方入口，摘要不作最终证据。网络故障最多重试两次，正常零结果不是故障。

按 [search-index.json](search-index.json) 的网站与任务路由，只加载本题流程。选定浏览器渠道后，已实现的执行函数优先一次完成填条件、提交、等待与读取；当前控件唯一性、模式或页面归属检查失败时才转原生Playwright重新观察。官方帮助一次读取相关段落，共享给多个选项；动态计数、排名、标准状态仍按题查询。证据够用即答复，不追加同义搜索或重复来源；保存仅在需要归档时进行。

刷题册的259道示例学习检索方法，不代表正式题会出现原题，也不提供本题答案缓存。提取本题题名、作者、机构、年份、资源类型和排序等参数，不能沿用示例实体或为减少结果增加未要求限制。站点流程需区分“入口已定位”“查询已验证”“受阻待定位”“已停用”；首页可达不能提升为查询已验证。

搜索结果或详情开新标签页时，由点击前监听与当前条件回显/记录标识共同确认目标；只在已确认结果容器中定位记录。列表有同名链接时以篇名、作者、年份或唯一ID区分，不以链接顺序猜。题目问“第n条”时保留当前查询、排序和每页数量，明确分页后读取该条，不能额外收窄条件再声称排名成立。旧题延迟弹窗和旧列表不作当前证据；结果页验证完成后重新观察，从原步骤继续。

## 官方API与指南

已有证据充分就结束。需要补证时，用已知端点直接获取本题字段，或读取对应指南的相关段落；不先浏览API根页、逐站探测接口或打开数据库高级检索来回答功能题。官方公开API是独立渠道，浏览器受阻不代表API不可用，反过来也一样。

站点及流程原有 `status`、控件、`execution` 和完成标志记录浏览器验证；新增 `retrieval_channels` 单独列API/指南的文档、实测时间、适用范围与障碍。只读本题相关流程的渠道；有渠道元数据不表示 `runSearch()` 已实现HTTP调用，直接请求无需浏览器session。样例请求成功只验证该端点和所读字段，不证明全库、所有筛选或本题已核验。

| 来源与需求 | 已知官方路径 | 适用范围与2026-10-10现场结果 |
| --- | --- | --- |
| Crossref：已知DOI的登记题录 | `GET https://api.crossref.org/works/{doi}`；[REST说明](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) | 单条JSON实测200，核对 `message.DOI/title/author/container-title/published-*`；字段缺失转出版方/全文，不能代替知网等指定库统计 |
| DOI：未知登记渠道的记录入口 | `GET https://doi.org/api/handles/{doi}?type=URL` 或 `https://doi.org/{doi}`；[解析说明](https://www.doi.org/the-identifier/resources/factsheets/doi-resolution-documentation) | 校赛给定中文DOI的URL解析实测200；核对 `responseCode/handle/values`。返回地址只用于定位，目标记录实际字段才证明答案 |
| PubMed：检索、PMID题录及作者单位 | `https://eutils.ncbi.nlm.nih.gov/entrez/eutils/` 下 `esearch.fcgi`、`esummary.fcgi`、`efetch.fcgi`；[官方接口指南](https://dataguide.nlm.nih.gov/eutilities/utilities.html) | 指南已停更，仅用于端点定位，限制以当前说明为准；本机ESearch网络/TLS失败，ESummary/EFetch未实测，避免每题盲重试 |
| PubMed：字段、短语、日期与检索翻译 | [PubMed User Guide](https://pubmed.ncbi.nlm.nih.gov/help/) | 按对应段落核对规则；ESearch须检查 `querytranslation`、警告/错误，不能把API默认顺序当网站Best Match |
| arXiv：ID/版本的元数据 | `GET https://export.arxiv.org/api/query?id_list={id}&max_results=1`；[API指南](https://info.arxiv.org/help/api/user-manual.html) | 本机实测429，保留限流状态；Atom元数据不代替PDF内容/页数，版本按题指定 |
| 世界银行：指定国家、指标和年份 | `GET https://api.worldbank.org/v2/country/{country}/indicator/{indicator}?date={year}&source={source}&format=json`；[API说明](https://datahelpdesk.worldbank.org/knowledgebase/articles/889392-about-the-indicators-api-documentation) | 指定国家/年份/数据源的单条JSON实测200；核对指标定义、单位、`sourceid/date/value/lastupdated`，多条时覆盖分页 |

| 知网、万方：产品指南 | 知网已观察到 `http://service.cnki.net/helpcenter/`；万方专业检索页的使用说明入口 | 本轮未取得充分指南正文，保留待核验；搜索结果只定位官方指南，实际正文/当前界面才支持答案 |

API参数用本题实体、日期字段、类型、精确/模糊及排序；以URL参数编码器处理中文、DOI及检索式，不手工拼接未转义表达式。统计与“第n条”仅在同库、全条件、查询解释、排序和分页一致时走API；否则读网站实际结果。Crossref被引量不等于其他数据库被引量，接口 `null`/缺失字段、加载中或失败不是零值/零结果。

不把所有DOI送入Crossref；该库没有记录不等于DOI不存在。已有正确官方落地页时直接读所问字段，无需再查登记机构；渠道未知才用解析路径，保留返回的真实URL，不从DOI后缀猜期刊或日期。只问记录中的物质、作者、导师、关键词等字段时不下载全文；已知PMID直接定位记录，PubMed的物质索引、MeSH及正文中的物质不能混为一类。Completion Date `[dcom]` 不用发表日期代替，Affiliation也不自动意味着第一作者单位。[PubMed官方字段说明](https://pubmed.ncbi.nlm.nih.gov/help/#search-field-tags)

读取HTTP状态、响应类型及实际字段。遵守当前响应限流头和官方约束；429按 `Retry-After` 或文档冷却，不能立即循环重试；认证、验证码或TLS错误不关闭验证、不猜令牌。未公开接口只有已实际观察到授权网页的请求且当前权限允许时才考虑，不靠猜URL或复用未知凭证。一次失败后选择能补缺口的渠道，普通网络故障仍受最多两次重试约束。

**免密钥接口的限流要有退避，并准备备用渠道。** 实测 Semantic Scholar 的 `paper/search` 在无 API key 时连续四次查询只有一次返回 200，其余均 429；按 `Retry-After` 或指数退避（每次至少加倍间隔）重试，不要立即循环。需要同一指标的第二来源时用 OpenAlex 的 `works` 端点交叉印证结论方向——它免密钥且实测稳定，但**数值属于另一口径**：同题引文数与 Semantic Scholar 相差约一成，排序一致而绝对值不同，因此只在题目未指定来源时作为独立证据，题目指定某工具时不得用备用源数值替换其数字。备用渠道失败同样不构成“该记录不存在”或“数值为零”。

**搜索引擎不可靠，优先官网直连。** 实测 Bing、百度、DuckDuckGo 在连续查询后会转为人机验证页，返回正常 HTTP 状态但正文是验证页面，不是结果。不要把验证页当作“无结果”，也不要在多个引擎之间反复重试；改为直接访问候选官方站点（题录页、年度报告页、机构库、官方 API），必要时先观察再定位。搜索摘要同样不能作为最终证据。

## 组合检索与统计

只在需要组合字段、范围及逻辑关系查询具体记录或统计时，优先使用本库专业/高级检索；DOI、完整题名和唯一编号可直达或普通精准检索，不能为简单定位增加模式切换。首次确认本库当前专业字段与语法，必要时使用高级字段组合，并在 `recordSearch` 中记录实际模式和回退原因。功能、定义、检索语法、期刊导航、RSS地址、期刊评价及学术热点各用对应说明或专用模块，不送入通用文献专业检索。

- 先选择题目要求的资源库，再填写检索式和日期条件。字段、精确/模糊、同义词或中英文扩展、文献类型与排序必须忠于题意；统计题不能擅自增加限制或关闭题目要求的扩展。
- 各库字段代码和匹配符分别核对，不把知网语法套到万方、维普或同厂商另一产品。含引号、括号或运算符的检索词按当前官方帮助转义，不拼成未经检查的表达式。
- 正常零结果可检查语法和拼写，再按题意放宽匹配；语法报错、加载中和权限错误不能记录为 `empty`。专业检索只提高定位效率，答案仍需正确题录、详情或全文证明。
- 只有查找某篇特定文献时可用给定的完整篇名/DOI加作者等进行定位。题目询问某字段检索结果总量、排名或第几条时，严格保持原检索式、条件及排序，不能为定位单篇额外收窄统计口径。

只问是否超过阈值时，条件一致的官方总数字段足够，不展开逐条列表；只问前n名则读相应排名范围及口径，不下载全部题录。候选项用于读取和比较所问字段，不能附加为筛选条件来证明“全库最高”。期刊评价报告区分报告版年与指标年，字段精确到影响因子/篇均被引/H指数；结果分析的关键词、机构、作者及学术热点分别读取对应模块。

链式题把前一步的DOI、记录ID、作者/机构及刊期传给下一步，不重新从泛化关键词搜索；上游身份或版本未确认时暂停依赖步骤，继续无依赖的部分。先辨“原文引用了谁”与“哪些文献引用原文”的方向；第n条参考文献保留原列表顺序，不采用被引列表。政策/标准版本比较读取题设的两份原文；同机构的能力框架、生成式AI指南等不同文件不能因名字近似而互替。题目只写“该专利”且缺少前文/编号时先说明对象缺口。

已在2026-10-09用 Chrome 观察到的入口：知网[高级/专业检索](https://kns.cnki.net/starter/advanced)（当时转到 `kns8s/AdvSearch`），万方[高级/专业检索](https://s.wanfangdata.com.cn/advanced-search/paper)。进入后仍需确认可见的“专业检索”模式；URL相同不能证明已切换。知网当时页面列出 `SU` 主题、`TI` 篇名、`AU` 作者、`AF` 作者单位、`KY` 关键词、`DOI` 等，实际专业语法以页面“专业检索使用方法”为准；万方当前模式提供中文字段按钮和逻辑关系，优先由真实字段按钮生成表达式，避免猜字段代码。页面改版后重新观察。

维普[官方检索规则](https://www.cqvip.com/helpcenter/advancesearch)说明其当前官网支持字段与 `AND` / `OR` / `NOT` 及括号组合，并区分模糊与引号中的精确匹配；只对该产品适用，不能与旧期刊平台或智立方互套。

| 题目字段 | 证据要求 |
| --- | --- |
| 文献 DOI、作者、单位、关键词 | 正确题录，核对篇名、作者与年份，不能只凭近似题名 |
| 第 n 条参考文献 | 原文或完整参考文献列表及顺序，记录条目和定位 |
| 图书 ISBN、章节、馆藏 | 核对版本、译名、作者与具体馆藏；章节需目录或全文 |
| 国家标准 | 标准号、版本、状态、发布/实施日期；起草人等需详细字段或全文 |
| 法规、专利、商标、证书 | 官方记录及适用时点；不输入用户未提供的个人身份信息 |
| 结果数、占比、排名、被引量 | 指定数据库、字段、匹配方式、类型、起止日期、筛选、排序与查询时间；保留分子分母 |
| PDF 页数、图数、表名 | 正确版本及实际PDF；页数可读元数据，表名可读文字，图数须覆盖所问范围并按需看图；区分正文页码和文件物理页码 |
| 视频总时长 | 对应记录及播放器初始化后的总时长/官方元数据，区分总时长与当前播放位置；无需完整播放 |
| 工具功能与界面 | 当前官网/帮助或实际授权界面；区分桌面版/网页版和版本、权限 |
| 检索公式与计算 | 本题原文输入、适用公式、实际复算证明；相似数值不能代替计算 |

## 全文与页面核对

题目指名"第 n 页""最后一个单词""文件大小""共几页"时，答案就在指定版本的全文字节里。以下三条按实测得出，违反其中任一条会直接答错。

**扫描件无文本层时改用页面图像。** 先试文本提取；提取结果为空（不是零星缺字）说明该 PDF 没有文本层，此时**不得**据此判断"页面无内容"或"找不到"，应导出该页图像后识别。老学位论文、古籍、地图、公报的扫描件普遍如此：某 1993 年学位论文 153 页全部为 CCITT 传真压缩图像，文本提取全空，逐页导出图像后才读到内容。反向也要区分：文本提取到一部分而缺另一部分，属于提取质量问题，不是无文本层。

**按题目页码定位前先验证页码偏移。** 印刷页码与 PDF 物理页序常因前置页（封面、目录、罗马数字页）而不一致。直接按 PDF 序号取"第 n 页"会取到错误的页。做法是取几页的页脚实际数字，确认偏移后按偏移换算，并把该页页脚数字作为定位证据；同一次任务里偏移通常恒定，但仍应至少核对两页。正文页码与文件物理页码也要在答复中区分。

**指定工具时用该工具的口径。** 题目写明"在某工具/某数据库中"时，同一指标在该工具与其他来源的数值可能不同（如某文献的引文数在同一工具与其数据上游、其他聚合库之间相差约一成），排序可能一致而绝对值不一致。此时以**题目指定工具**给出的数字为准，其他来源只用于交叉印证结论方向，不替换其数值。若指定工具不可达，如实说明并标明改用来源，不默认为等价。

## 本地计算与准备规则

题内数据和关系完整时直接推导，依据标为题内数据，不为外部来源或证明文件调用浏览器。需要确定性复算可用本地代码，或可选的 `session.calculate(question, {operation, inputs, inputQuotes})`：`retrieval-metrics` 使用 `relevantTotal`/`retrieved`/`relevantRetrieved`，`ratio-percent` 使用 `part`/`whole`。helper要求对应题干摘录并校验数值、分母后复算；输入缺失、矛盾或条件不符时指出关键缺口，不猜数值。此接口的保存、证明格式见 [browser.md](browser.md)，不是题内推导的必经路径。

准备规则按范围、排除条件、claims、出处及核验日期使用，可直接读卡答复。需要helper记录时再调用 `session.ruleCard(ruleId)` 和 `session.useRule(question, {ruleId, claims, application})`；`application`说明本题如何满足适用条件。注明准备核验日期及出处，不能写成本题刚刚访问。通用AND/OR/NOT不能证明CNKI精确/模糊匹配、字段代码、拆词或操作优先级等厂商特定行为；引用类型标识不能证明作者机构、完整人数或刊期。规则卡保存通用依据，不保存原题答案或动态排名。

仅凭模型记忆、没有适用规则、实际原始来源或题内可复算依据时，保持 `unverified` 并说明待核验。不能因为熟悉概念而声称官方已核验；也不为了取得一个网址检索无关论文。

## 单选、多选、判断

- **单选**：按题干选出唯一答案，检查其他选项是否应排除；出现多个可选项时标明冲突或题意缺口。
- **多选**：核查全部选项，记录每项应选、应排除或未知。只证实部分应选项不能标为整题已核验。
- **判断**：判正确须覆盖完整陈述及适用条件；判错误可用足以推翻原陈述的真实反例或不成立的必要条件。反例须落在题目范围内，不能用不同版本或不同产品代替。
- **否定题**：“错误的是”“不包括”等按题干评判应选性，避免将选项陈述的真伪直接当作选中与否。
- **选项变化**：保存应选的完整文字，再映射当前字母。旧题字母、旧顺序和动态答案缓存均不能代替本题判断。
- **证据缺口**：按选项标明已证实、已排除和未知，以及所缺字段/条款。先核验最能改变答案的疑点，共用一条规则或同页记录；其他部分只补缺口，不重新查询已证实条件。多选仍检查全项；单选仍确认唯一应选项，不能因找到一个看似错误项就跳过题意与其他冲突项。

## 核验状态

- `verified`：实际取得的原始页面/全文、官方API响应、已核验规则或本题可复算证明足以支持最终答案；条件适用且全部选项已判断。来源须可追溯，取得者可以是主代理或子代理，不以是否额外截图/落盘作为事实充分性的判据。
- `partial`：部分结论成立，仍有选项、日期、版本、条件或全文细节缺口。
- `unverified`：只有记忆、摘要或尚未达到要求的证据；可给标注“待核验”的候选。
- `blocked`：所需证据被登录、机构权限、验证码或网络阻挡，说明具体步骤。
- `conflict`：权威来源间矛盾，或材料答案与实际记录/算术不一致，列出差异。

可选预检仅说明指定目标的访问结果，不证明检索能力或本题答案。helper检查结构、当前选项映射及证据关联，无法机械证明引文语义或推理正确。

来源目录中的 `discovery` 表示发现渠道。查询该平台自身功能时，它的官方帮助可以是一手证据；查询外部事实时，搜索摘要仍不能替代原始发布方。helper的域名检查只确认目录关系，不能代替这项判断。

## 保存与答复

答案充分时直接回复，不强制 `beginQuestion()`、`saveAnswer()` 或来源落盘。需要helper归档时，`session.saveAnswer(question, answer)` 结构参照 [answer.schema.json](answer.schema.json)；该接口只处理其实际登记的证据，不手工伪造兼容记录。`answer` 为文字数组，`answer_labels` 为当前字母映射。判断题填写“正确”或“错误”；原题提供判断选项时保持当前映射。

`option_evaluations.verdict` 表示证据是否支持选作本题答案：`supported` 应选、`refuted` 应排除、`unknown` 未确定。选项文字忠于当前题目，不确定项不得强行写应排除。

可选归档可使用 `captureEvidence()` / `captureEvidenceBatch()`，同页摘录共用一次读取；截图只在视觉取证、诊断或用户要求时启用。已有保存记录用 `findEvidence()` 定位、`reuseEvidence()` 关联，保留原取得时间，不复制旧答案。计算/规则的helper来源使用对应接口返回值。直接原始工具证据按实际URL、内容和取得方式引用，不必转换成上述格式。登录墙和错误页仅作访问障碍，不能捏造网址、引文或已打开记录。

正文、API字段或PDF元数据足够时，不额外截图、渲染或播放媒体。`observe(..., {compact: true, focus: [...]})` 可减少返回量；`truncated` 为真或关键词未出现，均不能证明不存在。否定、量词、完整名单及排除项须读取足够上下文或完整所问范围，不必读取与结论无关的全部资料。

答复统一遵循 [SKILL.md的默认答复](../SKILL.md#默认答复)，此处不另设一套格式。必要补证和选项核验完成后直接答复，不反复润色或先生成完整JSON答案。受阻、待核验和冲突题仍说明会改变答案的关键缺口。用户要求归档时直接保存已有材料并读取 `saved.answer`；保存失败或格式不兼容不构成新的事实缺口，也不触发重复检索。不谎称helper已通过。

## 置信度

`confidence` 是根据本题证据完整性作出的估计，不是统计验证的正确率。模型可提供 `score`（0..100的整数）和 `basis`（原始证据及缺口的简短理由）；helper根据最终核验状态封顶并填充 `level`（`high` / `medium` / `low`，中文显示高/中/低）。未提供时按状态给出保守估计，不用虚构测试样本或概率解释分数。

| 最终核验状态 | 未提供分数时默认值 | 分数上限 |
| --- | --- | --- |
| `verified` | 95 | 99 |
| `partial` | 65 | 79 |
| `unverified` | 30 | 49 |
| `blocked` | 20 | 49 |
| `conflict` | 40 | 59 |

分数90及以上为高，60至89为中，低于60为低。helper不会为了达到默认值抬高主动给出的低分；证据或选项校验导致降级时重新封顶，保留 `basis` 并补充降级理由。默认值是保守显示约定，不能倒过来代替实际核验。

- 单选：评估唯一应选项及其余选项排除依据，否定题仍按题干应选性核验。
- 多选：评估整题所有应选、应排除和未知项；某个选项有确定证据，不代表整个选项组合已核验。
- 判断：评估完整陈述、量词与适用条件；只证明其中半句时降低置信度并说明缺口。
- 只有记忆或搜索摘要、全文受阻、权威来源冲突时，不因“很熟悉这道题”提高到已核验等级。

浏览器结果绑定及helper归档需要完整题目指纹，`runSearch(question, ...)` 会绑定当前题；原生transition或独立归档按需用 `beginQuestion(question)`。直接原始证据和题内推导无需这些接口。所有路径按当前选项文字重新判断字母。

用户给定省赛淘汰赛有单选30道、多选15道、判断10道，共55题，满分100分，限时60分钟。不推定各题分值，不自动启动考试倒计时；减少无关读取和重复工具调用，同时保留会改变答案的关键证据。
